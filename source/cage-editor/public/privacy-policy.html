What data we process and why

  • Sign-in and account data. Sign-in is provided by Microsoft Entra External ID. Depending on your account and sign-in, Microsoft processes identity data such as your username and account identifiers. CaGE uses the sign-in identity to authenticate requests and associate you with organizations. The editor keeps authentication data, including tokens, in your browser’s session storage.
  • Content you create. The editor stores organization names, game/title names, version information, attribute names and types, and tag names. Organization membership records also associate your sign-in username with an organization. Do not enter personal or sensitive information into this content unless it is necessary for your use of the service.
  • Game service data. When a match is created, the game service generates a match identifier and stores a JSON record containing that identifier. The current implementation does not include player details in that record.
  • Technical and diagnostic data. Microsoft Azure and the application’s diagnostic logging may process technical information needed to deliver, maintain, and secure the service. The precise information collected, including any request metadata, and its retention period depend on the deployed Azure logging configuration.

We use this information to provide the editor and game service, authenticate users, manage organization access, and maintain and secure the application. The operator must confirm and document the applicable legal basis for each purpose before publication (for example, performance of a service contract or legitimate interests in operating and securing the service).

Storage and service providers

CaGE is hosted on Microsoft Azure. Application resources are deployed in the Germany West Central region where the relevant Azure service supports it. The editor stores its application records in Azure Table Storage, and the game service stores match records in Azure Blob Storage. Microsoft Entra External ID provides sign-in.

Microsoft processes data to provide these cloud and identity services. Some provider operations, such as identity processing, support, or diagnostics, may be subject to Microsoft’s service configuration and terms and may not be limited to the hosting region. The operator should confirm the applicable Microsoft agreements, processing locations, and safeguards before publication.

We do not sell personal data.

Browser storage and cookies

The editor uses browser session storage for authentication state and tokens. The application code does not show analytics or advertising tracking. Microsoft’s sign-in service may use cookies or other browser storage as needed for authentication.

How long we keep data

Some content can be deleted through the application, but deleting versioned content may not remove it while it is needed by other versions. The application does not provide a dedicated account-deletion flow; contact the operator if you want account data removed. The current application does not define a general retention period or an automatic expiry/deletion process for match records. The operator must set and publish appropriate retention periods, including for diagnostic data and provider backups.
