What data we process and why

  • Sign-in and account data. Sign-in is provided by Microsoft Entra External ID. Depending on your account and sign-in, Microsoft processes identity data such as your username and account identifiers. CaGE uses the sign-in identity to authenticate requests and associate you with organizations. The editor keeps authentication data, including tokens, in your browser’s session storage.
  • Content you create. The editor stores organization names, game/title names, version information, attribute names and types, and tag names. Organization membership records also associate your sign-in username with an organization. Do not enter personal or sensitive information into this content unless it is necessary for your use of the service.
  • Game service data. When a match is created, the game service generates a match identifier and stores a JSON record containing that identifier. The current implementation does not include player details in that record.
  • Technical and diagnostic data. Microsoft Azure and the application’s diagnostic logging may process technical information needed to deliver, maintain, and secure the service. The precise information collected, including any request metadata, and its retention period depend on the deployed Azure logging configuration.

Legal bases for processing

Our current assessment, which the operator should review, is that we process sign-in and account data, organization membership, and content you submit as necessary to provide the editor and game services you request (Article 6(1)(b) GDPR, performance of a contract). We may process technical and diagnostic information to operate, maintain, and protect the services, prevent misuse, and investigate faults based on our legitimate interests (Article 6(1)(f) GDPR). We will review whether any specific processing is required by law and update this policy if necessary. These are working assumptions, not legal advice.

Storage and service providers

CaGE’s Azure application and storage resources are deployed in the Germany West Central region where the relevant Azure service supports it. The editor stores its application records in Azure Table Storage, and the game service stores match records in Azure Blob Storage. Microsoft Entra External ID provides sign-in; its tenant geography is separate from the Azure resource region. Microsoft explains that an Entra tenant’s country or region is selected when the tenant is created and maps to a geo-location that may include multiple Azure regions. Azure residency commitments and exceptions vary by service. See Microsoft’s Entra data residency and Azure data residency information.

Microsoft processes data to provide its cloud and identity services. The applicable Microsoft agreement and Data Protection Addendum set out the processing terms and safeguards for covered services, including safeguards for applicable international transfers. The precise terms and service coverage depend on the operator’s agreement and configuration. A Germany West Central deployment does not by itself mean that every identity, support, or diagnostic operation takes place only in Germany or the European Economic Area. The operator should verify the Entra tenant’s assigned geography, the relevant service-specific commitments, and its applicable Microsoft contract.

We do not sell personal data.

Browser storage and cookies

The editor uses browser session storage for authentication state and tokens. The application code does not show analytics or advertising tracking. Microsoft’s sign-in service may use cookies or other browser storage as needed for authentication.

How long we keep data

Some content can be deleted through the application, but deleting versioned content may not remove it while it is needed by other versions. The application does not provide a dedicated account-deletion flow; contact the operator if you want account data removed. The current application does not define a general retention period or an automatic expiry/deletion process for match records. The operator must set and publish appropriate retention periods, including for diagnostic data and provider backups.
